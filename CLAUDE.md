# Mizan marketing site

Static site generated by `src/build.py` from `src/i18n_{en,ar,tr}.py` into `site/`.
`src/site.js` is copied verbatim to `site/assets/site.js`; edit the source, never the output.
See README.md for the full layout, the deploy rules, and the web -> app handoff constraints.

Regenerate after any change to `src/`:

```bash
python3 src/build.py
npx tailwindcss@3.4.17 -c src/tailwind.config.js -i src/input.css -o site/assets/styles.css --minify
```

## Billing today

The backend at `https://api.mizan-ai.org` (NestJS, in `../mizan-app/backend`) uses
**RevenueCat** for App Store / Google Play and still has a **Stripe** web checkout.

Web checkout is moving to **Paddle** (sandbox only so far). The site side is built and
switched by `.env`: with `PADDLE_CLIENT_TOKEN` set, `build.py` ships `cfg.paddle` (token +
six price ids) in the data island, adds the measured Paddle hosts to the CSP, and swaps
the pricing note to name Paddle; `site.js` then opens a Paddle overlay instead of calling
`POST /billing/checkout`. With it unset, the site is byte-for-byte the backend flow.
Checkout requires a signed-in Mizan account (email prefilled and locked; account id in
`customData.mizan_user_id`). No Paddle webhook or entitlement exists yet (Task 03), so the
success page correctly stays in "being activated".

## Paddle integration

When writing or modifying code that integrates with Paddle:

- Always check current Paddle documentation via the `paddle-docs` MCP server before
  suggesting code. The Paddle API and SDKs evolve frequently; do not rely on training data alone.
- Use the official Paddle SDK for the language in use:
  - Backend (`../mizan-app/backend`, NestJS / TypeScript) -> `@paddle/paddle-node-sdk`
  - Frontend (`src/site.js`, vanilla JS, no bundler) -> Paddle.js loaded from Paddle's CDN
  - `src/build.py` is a static generator and must never call the Paddle API.
- All development uses the sandbox environment. Sandbox API keys contain `_sdbx`; sandbox
  client-side tokens are prefixed with `test_`. Live client-side tokens are prefixed with `live_`.
- Always verify webhook signatures before acting on the payload:
  - Node: `paddle.webhooks.unmarshal()`
- Allowlist Paddle's webhook source IPs on the server. Fetch them from
  `https://api.paddle.com/ips` (live) or `https://sandbox-api.paddle.com/ips` (sandbox);
  never hard-code the list.
- For destructive account changes (updating prices, archiving products, cancelling
  subscriptions, deleting or recreating notification destinations), ask for explicit
  confirmation before calling the `paddle-sandbox` or `paddle-live` MCP server.
- Use `paddle-sandbox` by default. Only call `paddle-live` when the prompt explicitly
  mentions live, production, or real customer data.
- API keys, client-side tokens, and webhook secrets live in environment variables; never
  inline credentials into code. Client-side tokens reach the browser only through the
  `mizan-data` JSON island that `build.py` emits, read from an env var at build time.
- The Paddle CSP hosts live in `PADDLE_HOSTS` in `src/build.py`, measured with a headless
  run under the real CSP (Paddle.js needs `<env>cdn.paddle.com` + `'unsafe-inline'` in
  style-src). Re-measure the production row before go-live; never hand-edit `site/_headers`.
- Never deploy a `PADDLE_ENV=sandbox` build to production; the build prints a warning.
- Never `Paddle.Environment.set('sandbox')` in the live build; live is the default.
- Keep all user-visible strings in the `i18n_*.py` files, in all three languages. Nothing
  user-facing is hardcoded in JavaScript.
- Catalog source of truth is `PRICES` / `PLAN_KEYS` in `src/build.py`. The idempotent seed
  script `../mizan-app/backend/scripts/seed-paddle-catalog.mjs` mirrors it and creates the
  three products and six prices in sandbox (or live with `--live`); keep the two in sync.
  Products carry `custom_data.plan` and prices `custom_data.period`, so webhooks can name
  the tier without an env lookup.
